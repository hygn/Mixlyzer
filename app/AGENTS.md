# AGENTS: app/ (Mixlyzer)

The details of `app/`: the start, the splash and the window's wiring. The root `AGENTS.md`'s rules (run, layers, owners, change guidelines) apply here too; read it first.

## Map
- `app/`: Qt entrypoint and top-level window wiring.
  - `main.py`: app bootstrap (the UI language first, before the UI is imported), dark palette, font loading, library-version migration flow. Kept light: a spawned worker process imports the main module again, so `app.window` is imported by the startup, not at the top.
  - `startup.py`: the startup splash (the task, what it is doing, a Task and an Overall progress bar, and under them the console's last lines: `startup_console.py`, `ConsoleLines` tapping sys.stdout / stderr from `main()`'s start (the print hook, installed later, writes through it; taken out when the splash closes), drawn as a terminal's: the time since the start, a coloured tag per source (`[Startup]`, `[AudioEngine]`, ...), a finished task's time right-aligned, a failure in the danger colour; the engine's lines, printed on its relay thread, drawn at the next repaint) and the slow work done before the window opens, in order: the heavy imports, the Python audio engine's numba kernels (JIT, from numba's disk cache; skipped when the native engine is built), FFmpeg's first run, the search readers (`reading.warm_up`), the language pickers' names and the width they need (`ui.widgets.language_picker.warm_up`), the library's stores checked against library.db (`jobs.check_stores`, the owner's first job), every stored reading's search keys (`reading.keys`' LRU cache), then `AppWindow(progress=)`. numpy's and scipy's OpenBLAS load with one thread in this process (`one_blas_thread()`, first in `main()`: the GUI does no heavy linear algebra, and each OpenBLAS sets aside buffers per thread, about 1 GB committed on 16), the variable taken back once they have, so the spawned worker processes keep a thread per core. Each task's weight is its measured time; events are taken between updates except while the window is built (only the splash repainted there, so no timer reaches a half-built window).
  - `audio_report.py`: the audio setup printed at the start (`[AudioEngine]` lines: the engine that plays and why, the master's device / API / mode / buffer, the process's priority, the mixer's switches, MIDI); what the engine then opened follows as its own lines.
  - `diagnostics.py`: the menu's Diagnostics (`ui/windows/diagnostics_dialog.py`: read there, then copied or saved by the user; the app sends nothing): the app's version (`system/version.py`, pyproject.toml's), the system's, FFmpeg's, the audio setup (`audio_report`'s lines), the output devices and MIDI inputs the engine lists, each output's buffer since the start (`BufferRecord`, fed by `EventBus.sig_output_buffer`: the time played and the dropouts summed, the last state) and the console's last 3000 lines (`CONSOLE`, installed first in `main()`, whether the log file is written or not); the home folder written `~`, the account's name `<user>`. Its words are English, as the logs.
  - `window.py`: `AppWindow`, workflow wiring, EventBus wiring, External Sync, metronome, model updates. Edits not saved are never lost without a question (`_with_edits_resolved`): before a load, the unload, a library reanalysis of the deck's track and quitting (`closeEvent`) the user picks Save (then the action, once `EditPanel.save_then` has stored them), Discard or Cancel; an External Sync load offers no Cancel (the other software has moved on) and takes the last track asked while the box is open (one asked while a box for something else is open is asked once that is settled, `_external_load_waiting`; one whose save fails is asked again, the edits kept; the question's state one value, `_Edits`: IDLE / ASKING / CLOSING, nothing asked once the quit is settled); a reanalysis result that comes while the editor holds edits not saved goes to the library only.

## App Flow
- Entry is `app.main:main()`.
- On startup the app:
  - makes the app folder the current folder (`system.resource_paths.app_folder`: the package folder in a build, else the project root), whatever folder it was started from: `config.json`, the library and the caches are always the app's, and no program or `config.json` of another folder is taken,
  - sets the UI language (`config.json`'s `viewconfig.language`, only read),
  - runs Python's garbage collector on the GUI thread only (pyqtgraph's `GarbageCollector`: automatic collection off, a 1 s timer collecting by the same thresholds; the tests' `qt_env` too): run automatically it ran on whichever thread allocated (the library's owner, a decode), and a Qt object in a cycle freed there was destroyed off the GUI thread, its timers left to fire at it (an access violation),
  - shows the startup splash (`app.startup`),
  - loads `config.json` and `deck.json` (warning for each that could not be read and was kept aside),
  - ensures the library directory exists,
  - checks `library/VERSION`,
  - checks the on-disk library version through the migration adapter and stops on a mismatch,
  - runs the startup tasks (imports, JIT, FFmpeg, search readers and keys) and builds `AppWindow`, then shows it and closes the splash.
- `AppWindow` creates the shared `EventBus`, `DataModel`, `TimelineCoordinator`, `PlayerController`, `ExternalSyncController`, `SegmentReanalysisWorkflow`, and `MainPane`.
- UI state is mostly signal-driven. The loaded track's signals are the model's (`DataModel.sig_loaded`, `sig_beatgrid_changed`, ...), notifications only; listeners read current values from the shared `DataModel`.
